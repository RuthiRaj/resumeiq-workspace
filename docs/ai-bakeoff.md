## Method

- Corpus: `backend/tests/golden/synthetic_corpus.json` — synthetic resumes and job descriptions only; no real personal data.
- Cases per model per repeat: 11 (rewrite_bullet, explain_gap, extract_resume_fields, parse_job_requirements). Repeats: 1.
- Every call goes through the real gateway: redaction, cache, quota, retries, one repair attempt, then schema validation and the deterministic claim validator in report mode.
- `first-pass valid` counts outputs that needed no repair. `final valid` counts outputs that satisfied the schema after at most one repair attempt.
- `p50`/`p95` are nearest-rank percentiles of successful-call latency in milliseconds, measured around the provider HTTP call.
- `grounding errors` counts rejected claims (invented metrics, unsupported technologies/organisations, inflated titles, unsupported dates). A live result is only usable for a task whose grounding count is zero.

## Known gaps (v1)

- The claim validator is deterministic and lexicon-based: an unknown synonym of a supported technology can be rejected (fail-closed by design, ADR-030).
- Only one repair attempt is measured; a second repair is not attempted.
- Latency is measured around the HTTP call and excludes queueing on the provider side before the request is accepted.
- The corpus is small (synthetic), so the numbers are indicative, not a benchmark.
